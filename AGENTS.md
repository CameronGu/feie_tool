# FEIE Window Optimizer

Keep the application static and private by default. No backend, account or external travel-data submission. Do not push, publish or deploy without user authorization.

Read `docs/CALCULATION-SPEC.md` before changing counting rules. Preserve one versioned travel-history source and derive calculation/report evidence from it. Never infer foreign presence from an empty U.S. list, erase history on year changes, or treat proposed days as completed evidence.

Maintain `docs/RELEASE-PLAN.md`, `docs/PROGRESS.md` and `docs/RELEASE-READINESS.md`. Add meaningful regression tests for logic changes. Verify with `npm run check` and relevant `npm run test:e2e` workflows. Keep tax-law uncertainty explicit; no full FEIE eligibility or actual tax-savings claims.
